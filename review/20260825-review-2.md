## 2. P0 신규 — 헤드 conv padding 누락

### 2.1 증상

`ConvModule`의 기본 인자를 `kernel_size=1, padding=0`으로 변경하면서,
`models/head.py:9,10,15,16`의 `ConvModule(..., kernel_size=3)` 호출이 **padding 없이 생성**됩니다.

```
ConvModule 시그니처: (self, in_channels, out_channels, kernel_size=1, stride=1, padding=0, groups=1)
ConvModule(8,8,kernel_size=3) -> Conv2d(8, 8, kernel_size=(3,3), stride=(1,1), bias=False)
                                  ↑ padding 지정 없음
  입력 80x80 -> 출력 78x78

DecoupledHead 입력 80x80 -> 출력 76x76   (3x3 valid conv 2회 = -4)
DecoupledHead 입력 40x40 -> 출력 36x36
DecoupledHead 입력 20x20 -> 출력 16x16
```

Neck 출력까지는 정상(80/40/20)이며 **헤드에서만 축소**됩니다.

```
backbone 출력: [(1,96,80,80), (1,192,40,40), (1,384,20,20)]   ✅
neck 출력    : [(1,128,80,80), (1,128,40,40), (1,128,20,20)]  ✅  총 grid 8400
head 출력    : cls (2, 7328, 80)                              ❌  기대 8400

  stride  8: 5776 (76²)   기대 6400 (80²)
  stride 16: 1296 (36²)   기대 1600 (40²)
  stride 32:  256 (16²)   기대  400 (20²)

points x 범위: 4.0 ~ 604.0   (이미지 폭 640)
```

### 2.2 피해 — 두 가지가 동시에 발생

**① 경계 영역 원리적 미검출**

우측·하단 **36px 구간에 grid point가 존재하지 않습니다.** 해당 영역의 객체는 어떤 학습을 해도 검출될 수 없습니다. assigner 실측에서도 확인됩니다:

```
우측하단 경계 (40x40)   positive=1   레벨별={8: 1, 16: 0, 32: 0}
```

**② 좌표계 전체의 계통 오차**

3×3 valid conv 2회를 거치면 출력 픽셀 0의 실제 수용영역 중심은 **입력 픽셀 2**입니다.
그러나 `make_grid_points`는 이를 0으로 가정하고 `(0+0.5)*stride`를 부여합니다.

| stride | 실제 중심 | 코드가 부여한 값 | 오차 |
| :---: | ---: | ---: | ---: |
| 8 | (2+0.5)×8 = 20 | 4 | **16 px** |
| 16 | (2+0.5)×16 = 40 | 8 | **32 px** |
| 32 | (2+0.5)×32 = 80 | 16 | **64 px** |

모든 박스 예측에 이 오프셋이 실립니다.

> ⚠️ **이 버그는 loss가 정상적으로 하강하기 때문에 증상이 드러나지 않습니다.**
> 학습은 되지만 mAP 상한만 조용히 깎입니다. 가장 찾기 어려운 종류의 결함입니다.

### 2.3 수정

```python
# models/head.py — DecoupledHead.__init__ 의 4곳 모두
self.cls_convs = nn.Sequential(
    ConvModule(in_channels, hidden_channels, kernel_size=3, padding=1),
    ConvModule(hidden_channels, hidden_channels, kernel_size=3, padding=1)
)
self.reg_convs = nn.Sequential(
    ConvModule(in_channels, hidden_channels, kernel_size=3, padding=1),
    ConvModule(hidden_channels, hidden_channels, kernel_size=3, padding=1)
)
```

**재발 방지 권장** — 기본 인자에 의존하지 말고 padding을 자동 계산하십시오.

```python
class ConvModule(nn.Module):
    def __init__(self, in_channels, out_channels, kernel_size=1, stride=1, padding=None, groups=1):
        super().__init__()
        # padding 미지정 시 'same' 크기를 유지하도록 자동 계산.
        # 기본값을 0으로 두면 호출부에서 k=3 을 쓸 때 조용히 피처맵이 줄어듭니다.
        if padding is None:
            padding = kernel_size // 2
        ...
```

**검증**:

```python

assert out['cls'].shape[1] == 8400
assert out['points'][:,0].max().item() == 636.0
```

## 3. P0 잔존 — Int8 PTQ 추론 불가

`QuantStub`/`DeQuantStub`과 `fuse_modules` 도입은 올바른 방향이었고, 그 덕에 1차의 `quantized::conv2d.new` 에러는 사라졌습니다. 그러나 다음 벽에 막힙니다.

```
fuse_modules 적용된 ConvModule: 31개
ConvNeXtBlockNPU 개수: 12  (이 블록의 dwconv+BatchNorm 은 fuse 대상 아님)
fuse 후 남은 BatchNorm2d: 16개
Int8 변환된 Conv2d: 80개
FP32 22.62MB -> Int8 7.06MB
❌ Int8 추론 실패:
   NotImplementedError: Could not run 'aten::silu.out'
                        with arguments from the 'QuantizedCPU' backend
```

### 3.1 원인 2가지

**① SiLU는 eager-mode 양자화 커널이 없습니다.**
PyTorch `fuse_modules`가 지원하는 조합은 `['conv','bn']`, `['conv','bn','relu']`, `['conv','relu']` 등이며
**ConvBnSiLU 퓨전은 존재하지 않습니다.** SiLU가 독립 연산으로 남아 QuantizedCPU에서 실행되지 않습니다.

**② 백본이 전혀 fuse되지 않습니다.**
`utils/quantize.py:30-32`가 `ConvModule`만 순회하므로,
`ConvNeXtBlockNPU`의 `dwconv`+`norm` 12쌍과 stem·downsample의 BN 4개, **총 16개 BatchNorm이 그대로 남습니다.**

### 3.2 검증 단계 부재 — 실패가 성공으로 보고됨

1차 리뷰 체크리스트 항목이었던 "convert 후 추론 검증"이 여전히 없습니다.
그 결과 `utils/quantize.py`는 **깨진 모델을 저장하고도 성공을 출력**합니다.

```
🚀 NPU 배포를 위한 Int8 PTQ 파이프라인 시작...
Calibrating batch 1/2...
Calibrating batch 2/2...
✅ Int8 PTQ 양자화 변환 완료! (저장 위치: exports/sota_detector_nano_int8.pt)
```

실행 중 다음 경고도 확인됐습니다 — eager 양자화 API 자체가 deprecated 경로입니다.

```
UserWarning: torch.quantize_per_tensor, torch.quantize_per_channel and other quantized
tensor creation functions ... are deprecated and will be removed in a future PyTorch release.
```

### 3.3 권장 해결 — 셋 중 택일

| 안 | 내용 | 장단점 |
| :---: | :--- | :--- |
| **(a)** | 양자화 경로에서만 `nn.SiLU` → `nn.Hardswish` | `quantized::hardswish` 커널 존재. NPU 친화도도 SiLU보다 높음. 정확도 재검증 필요 |
| **(b)** | `torch.ao.quantization.quantize_pt2e` 로 전환 | torch 2.13 권장 경로. deprecation 회피 |
| **(c)** | ONNX Runtime static quantization (QDQ) | NPU 컴파일러가 QDQ ONNX를 요구한다면 실무적으로 가장 안전 |

**어느 쪽을 택하든 반드시 추가하십시오**:

```python
model_int8 = quant.convert(model_prepared)

# ✅ 저장 전에 반드시 실제 추론으로 검증 — 없으면 깨진 모델이 성공으로 보고됩니다
try:
    with torch.no_grad():
        model_int8(torch.randn(1, 3, 640, 640))
except Exception as e:
    raise RuntimeError(f"Int8 모델이 추론 불가 상태입니다. 저장을 중단합니다: {e}") from e

torch.save(model_int8.state_dict(), save_path)
```

## 4. P1 — 신규 및 잔존 이슈

### 4-1. 🟠 평가 시 ColorJitter가 꺼지지 않음

`eval.py:33`이 `TrainTransforms(img_size=(640,640), p_flip=0.0)`으로 증강을 끄려 하지만,
`data/transforms.py:16`의 밝기/대비 지터는 `p_flip`과 무관하게 **자체 하드코딩 확률로 동작**합니다.

```python
# data/transforms.py:16 — p_flip 과 연결되어 있지 않음
if random.random() < 0.5:
    image = TF.adjust_brightness(...)
    image = TF.adjust_contrast(...)
```

**실측** (`p_flip=0.0`으로 동일 입력을 8개 seed로 통과):

```
seed별 평균 픽셀값: [0.5, 0.56949, 0.5, 0.50884, 0.42063, 0.5, 0.5, 0.43017]
-> 켜져 있음 ❌ (5종)
```

**평가가 비결정적이고 증강된 입력으로 수행됩니다.** mAP가 실제보다 낮게, 매 실행마다 다르게 나옵니다.

**수정**: 지터도 인자로 분리하거나, 1차 수정에서 삭제된 `ValTransforms`를 복원하십시오.

```python
class ValTransforms:
    """평가/추론용. 어떤 무작위 증강도 적용하지 않습니다."""
    def __init__(self, img_size=(640, 640)):
        self.img_size = img_size

    def __call__(self, image, targets):
        if not isinstance(image, torch.Tensor):
            image = TF.to_tensor(image)
        _, h0, w0 = image.shape
        image = TF.resize(image, list(self.img_size))
        sx, sy = self.img_size[1] / w0, self.img_size[0] / h0
        if targets['boxes'].numel() > 0:
            targets['boxes'] = targets['boxes'] * torch.tensor([sx, sy, sx, sy])
        return image, targets
```

### 4-2. 🟠 박스 없는 이미지는 flip되지 않음

`data/transforms.py:29`의 hflip 블록이 `if targets['boxes'].numel() > 0:` **안에** 중첩돼 있습니다.

```
p_flip=1.0 으로 20회 시도 -> 안 뒤집힘 ❌
```

**수정** — flip은 항상 수행하고, 박스 변환만 조건부로:

```python
if random.random() < self.p_flip:
    image = TF.hflip(image)
    if targets['boxes'].numel() > 0:
        boxes = targets['boxes']
        new_xmin = self.img_size[1] - boxes[:, 2]
        new_xmax = self.img_size[1] - boxes[:, 0]
        boxes[:, 0], boxes[:, 2] = new_xmin, new_xmax
        targets['boxes'] = boxes
```

### 4-3. 🟠 SSDLite 벤치마크는 여전히 320에서 실행

`min_size`/`max_size` 오버라이드는 FCOS·FasterRCNN에는 통하지만, **SSD 계열은 `fixed_size`가 우선**합니다.

```
ssdlite320: min_size=(640,) max_size=640 fixed_size=(320, 320)
            -> 실제 백본 입력 크기: (1, 3, 320, 320)   ❌
fcos:       min_size=(640,) max_size=640 fixed_size=None
            -> 실제 백본 입력 크기: (1, 3, 640, 640)   ✅
```

**교정하면 결과가 유리하게 뒤집힙니다** — 현재 벤치마크는 자기 모델에 **불리하게** 잘못돼 있습니다.

| 모델 | Latency | 비고 |
| :--- | ---: | :--- |
| Ours nano (5.61M) | **208.3 ms** | 640×640 |
| SSDLite (현행 벤치마크) | 126.0 ms | 실제로는 320×320 |
| SSDLite (`fixed_size` 교정) | **262.5 ms** | 640×640 — **동일 조건에서 우리가 더 빠름** |

```python
if hasattr(model, 'transform'):
    model.transform.min_size = (img_size,)
    model.transform.max_size = img_size
    # ✅ SSD 계열은 fixed_size 가 min/max_size 보다 우선하므로 함께 덮어써야 함
    if getattr(model.transform, 'fixed_size', None) is not None:
        model.transform.fixed_size = (img_size, img_size)
```

**FLOPs/MACs 출력은 여전히 없습니다** — `AGENTS.md`의 실험 추적 요구사항 미충족 (1차 STEP 9 잔여).

### 4-4. 🟠 ONNX에 grid 생성 로직이 동적 연산으로 박힘

```
Range 6, Shape 21, ConstantOfShape 3, Expand 6, Gather 6
outputs: cls ['batch', 'Concatcls_dim_1', 'Concatcls_dim_2']   ← (batch, 8400, 80) 이어야 함
         points ['Concatpoints_dim_0', 'Concatpoints_dim_1']
```

`make_grid_points`가 `forward` 안에 있어 `arange`/`meshgrid`가 그래프에 남았습니다.
grid는 입력 해상도가 고정되면 **상수**인데 동적 shape 연산으로 나갑니다.

- 다수 NPU 컴파일러가 `Range`/`ConstantOfShape`/`Expand`를 지원하지 않습니다
- 출력 shape이 동적이면 정적 shape을 요구하는 컴파일러에서 거부됩니다

**수정 방향**: grid/strides를 `register_buffer`로 미리 계산해 두거나,
아예 모델 밖(postprocess)으로 빼고 ONNX 출력은 `cls`/`reg`/`obj` 3개만 내보내십시오.

```python
# 예: 고정 해상도 기준으로 buffer 에 캐시
self.register_buffer('_points', torch.cat(pts), persistent=False)
self.register_buffer('_strides', torch.cat(sts), persistent=False)
```

### 4-5. 🟠 레벨별 스케일 분리가 없음

`TargetAssigner`가 객체 크기와 무관하게 모든 레벨에 동일하게 positive를 할당합니다.

```
대형   (300x300, 중앙)    positive=12   레벨별={8: 4, 16: 4, 32: 4}
중형   (100x100, 중앙)    positive=12   레벨별={8: 4, 16: 4, 32: 4}
소형   ( 32x32,  중앙)    positive= 8   레벨별={8: 4, 16: 4, 32: 0}
초소형 ( 12x12)           positive= 2   레벨별={8: 1, 16: 0, 32: 1}   ← 12px 객체를 stride 32 가 예측
경계   ( 40x40, 우하단)   positive= 1   레벨별={8: 1, 16: 0, 32: 0}   ← §2 padding 버그 여파
```

두 가지 문제:

1. **FCOS의 레벨별 size range(`[0,64]/[64,128]/[128,∞]`)에 해당하는 분리가 없습니다.**
   stride 32 헤드가 12px 객체를 예측하도록 학습되어, 멀티스케일 피라미드의 존재 이유가 약해집니다.
2. **`in_box AND in_center`라 객체당 positive가 12개로 매우 적습니다.**
   YOLOX는 `in_box OR in_center`로 후보를 넓게 잡은 뒤 SimOTA dynamic-k로 좁힙니다.

**수정 방향** (padding 버그 수정 다음 순위):

```python
# TargetAssigner 에 레벨별 회귀 범위 제약 추가
REG_RANGES = {8: (0, 64), 16: (64, 128), 32: (128, float('inf'))}
max_reg = torch.stack([l, t, r, b], dim=-1).max(dim=-1).values      # [N, M]
lo = torch.tensor([REG_RANGES[int(s)][0] for s in strides]).unsqueeze(1)
hi = torch.tensor([REG_RANGES[int(s)][1] for s in strides]).unsqueeze(1)
in_level = (max_reg >= lo) & (max_reg <= hi)
candidate = in_box & in_center & in_level
```

> 이후 SimOTA로 교체할 때는 **한 번에 하나씩** 바꾸십시오. size range와 SimOTA를 동시에 넣으면 원인 분리가 불가능합니다.
