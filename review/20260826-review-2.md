## 2. P0 잔존 — Int8 PTQ, 원인 1곳으로 좁혀짐

`FloatFunctional` 도입으로 **BiFPN 쪽은 완전히 해결**됐습니다. 블록 단위 격리 재검증 결과:

```
BiFPNBlock       (FloatFunctional add) : ✅ 통과   ← 3차에서 ❌ 였음, 해결
ConvNeXtBlockNPU (gamma_mul + skip_add): ❌ Mul operands should have same data type.
ConvNeXtBlock    (gamma fold 버전)      : ✅ 통과   ← 해법이 유효함을 실측 확인
```

파이프라인 실행 시:

```
RuntimeError: Int8 모델이 추론 불가 상태입니다. 저장을 중단합니다:
              Mul operands should have same data type.
```

### 2.1 원인

`models/backbone.py:24`의 `self.gamma_mul.mul(x, self.gamma)`가 문제입니다.

- `FloatFunctional.mul(x, y)`는 **두 피연산자가 모두 양자화 텐서**여야 합니다
- `self.gamma`는 `[dim, 1, 1]` 형태의 일반 Float `Parameter`이고 `x`는 QUInt8 → 타입 불일치
- `mul_scalar()`는 **파이썬 스칼라만** 받으므로 채널별 gamma에는 사용할 수 없습니다

> 3차 리뷰에서 제시한 `FloatFunctional` 코드가 `add`에는 정확했지만 `mul`에는 부적절했습니다.
> 채널별 텐서 곱은 `FloatFunctional`로 풀 수 있는 문제가 아닙니다.

### 2.2 해법 — gamma를 `pwconv2`에 접기(fold)

gamma는 `pwconv2` 출력에 채널별로 곱해지므로, `pwconv2`의 가중치·바이어스를 스케일하는 것과 **수학적으로 완전히 동등**합니다.

```
gamma ⊙ (W * x + b) == ((gamma ⊙ W) * x) + (gamma ⊙ b)
```

곱셈 연산 자체가 그래프에서 사라지므로 NPU 매핑에도 유리합니다. 학습 중에는 LayerScale로 그대로 두고, **양자화 직전에 한 번만** 접습니다.

```python
# models/backbone.py — ConvNeXtBlockNPU 에 메서드 추가
def fold_gamma(self):
    """
    LayerScale gamma 를 pwconv2 weight/bias 에 흡수합니다. 양자화 전 1회 호출.
    gamma * (Wx + b) == (gamma*W)x + gamma*b 이므로 수치적으로 동등하며,
    Int8 그래프에서 Float x QUInt8 곱셈 자체가 제거됩니다.
    """
    with torch.no_grad():
        g = self.gamma.reshape(-1)                        # [dim]
        self.pwconv2.weight.mul_(g.view(-1, 1, 1, 1))
        if self.pwconv2.bias is not None:
            self.pwconv2.bias.mul_(g)
        self.gamma.fill_(1.0)
    self.gamma_mul = None                                  # forward 분기 제거

def forward(self, x):
    residual = x
    x = self.pwconv2(self.act(self.pwconv1(self.norm(self.dwconv(x)))))
    if self.gamma_mul is not None:
        x = self.gamma_mul.mul(x, self.gamma)
    return self.skip_add.add(residual, self.drop_path(x))
```

```python
# utils/quantize.py — fuse 루프 확대 (§3.7 의 fuse 누락 13개도 함께 해결)
from models.backbone import ConvNeXtBlockNPU

for module in model_fp32.modules():

        fuse_modules(module, [['conv', 'bn']], inplace=True)
    elif isinstance(module, ConvNeXtBlockNPU):

        fuse_modules(module, [['dwconv', 'norm']], inplace=True)
```

- 5×5 depthwise + 4× 확장 pointwise가 고해상도 스테이지에서 반복

**선택지**:
1. nano의 `dims`/`depths`를 더 줄이고 헤드 채널을 64로 축소
2. 스템을 stride 8로 바꿔 P3 해상도를 낮춤 (소형 객체 mAP와 트레이드오프)
3. 티어 정의를 현실에 맞게 수정 (nano를 "경량 서버/고성능 모바일"로 재규정)

### 3.5 🟠 `FocalLoss`가 논문/표준 구현과 불일치

```
구현값 2.4003  vs  torchvision.ops.sigmoid_focal_loss 5.8858   (차이 3.4856)
```

`utils/loss.py:16`이 `alpha`를 **모든 항에 일괄 0.25**로 곱합니다.

```python
focal_loss = self.alpha * (1 - pt) ** self.gamma * bce_loss     # ❌
```

Lin et al. (2017)의 정의는 `alpha_t = alpha·y + (1-alpha)·(1-y)`이므로
**negative에는 0.75가 적용돼야 합니다 — 현재 3배 과소 가중**입니다.

cls loss가 positive 샘플에 대해서만 80차원 one-hot으로 계산되므로, 한 positive마다 79개의 "negative 클래스"가 3배 약한 신호를 받습니다. 클래스 간 판별력이 약해집니다.

```python
# utils/loss.py — 수정
def forward(self, inputs, targets):
    bce_loss = F.binary_cross_entropy_with_logits(inputs, targets, reduction='none')
    p = torch.sigmoid(inputs)
    pt = p * targets + (1 - p) * (1 - targets)
    alpha_t = self.alpha * targets + (1 - self.alpha) * (1 - targets)
    focal_loss = alpha_t * (1 - pt) ** self.gamma * bce_loss
    ...
```

> `pt = exp(-bce)` 근사 자체는 오차 5.96e-08로 문제없습니다. `alpha` 적용 방식만 고치면 됩니다.
> 검증은 `torchvision.ops.sigmoid_focal_loss`와 대조하는 것이 가장 확실합니다.

### 3.6 🟠 PTQ 캘리브레이션 데이터가 랜덤 노이즈

```

이미지 통계 mean=0.001  std=1.000  min=-4.97  max=4.71
```

`data/coco.py:40`의 `torch.randn(3, 640, 640)`을 `utils/quantize.py`가 그대로 캘리브레이션에 사용합니다.
자연 이미지(`[0,1]` 범위, mean≈0.45, 공간 상관관계 존재)와 분포가 **완전히 다릅니다**.

**§2의 수정으로 PTQ가 동작하게 되더라도, 이 데이터로 뽑은 activation 스케일은 무의미합니다.**

최소한의 방어책으로, 캘리브레이션 시 더미 모드를 거부하도록 만드는 것을 권합니다.

### 3.7 🟠 fuse 누락 13개 (2차부터 미조치) + 구조상 불가 3개

```
전체 BatchNorm 47개 → quantize.py 실행 후 16개 잔존
  ConvNeXtBlockNPU dwconv+norm : 12개  (Conv→BN 순서, fuse 가능한데 코드가 안 함)
  stem  Conv→BN                : 1개  (fuse 가능한데 코드가 안 함)
  downsamples BN→Conv          : 3개  (BN 이 Conv 앞이라 구조상 fuse 불가)
```

앞의 **13개는 §2.2 코드로 해결**됩니다.

뒤의 3개는 `models/backbone.py:55-58`이 `nn.Sequential(BatchNorm2d, Conv2d)` 순서라 **원리적으로 fold가 불가능**합니다. ConvNeXt의 "LayerNorm → downsample conv" 관례를 BatchNorm으로 그대로 옮긴 결과입니다.

```python
# models/backbone.py:55-58 — Conv 를 앞으로 보내면 BN 이 fold 되어 Int8 그래프에서 사라집니다
self.downsamples.append(nn.Sequential(
    nn.Conv2d(cfg['dims'][i], cfg['dims'][i+1], kernel_size=2, stride=2, bias=False),
    nn.BatchNorm2d(cfg['dims'][i+1])
))
```

> 정규화 위치가 바뀌므로 학습 곡선이 달라질 수 있습니다. NPU 배포가 목표라면 감수할 가치가 있으나, 변경 전후 오버피팅 테스트로 수렴성을 확인하십시오.

이번 라운드는 **"돌아간다"에서 "측정된다"로 넘어간 지점**입니다.

이것이 지표를 갖추는 일의 가치이며, 다음 단계는 **실제 COCO 데이터로 이 지표들을 다시 뽑는 것**입니다.

### 7-1. Int8 실패 지점 격리 (§2)

```python
import torch, torch.nn as nn, warnings
warnings.filterwarnings('ignore')
import torch.ao.quantization as quant
from torch.ao.quantization import QuantStub, DeQuantStub, fuse_modules
from models.backbone import ConvNeXtBlockNPU
from models.neck import BiFPNBlock, ConvModule

class Wrap(nn.Module):
    def __init__(self, inner, multi=False):
        super().__init__()
        self.q, self.inner, self.dq, self.multi = QuantStub(), inner, DeQuantStub(), multi
    def forward(self, *xs):
        xs = [self.q(x) for x in xs]
        o = self.inner(*xs)
        return tuple(self.dq(t) for t in o) if self.multi else self.dq(o)

def check(inner, xs, name, multi=False):
    w = Wrap(inner, multi).eval()
    for m in w.modules():
        if isinstance(m, ConvModule):
            fuse_modules(m, [['conv', 'bn']], inplace=True)
    torch.backends.quantized.engine = "qnnpack"
    w.qconfig = quant.get_default_qconfig("qnnpack")
    p = quant.prepare(w)
    with torch.no_grad(): p(*xs)
    q = quant.convert(p)
    try:
        with torch.no_grad(): q(*xs)
        print(f"  {name}: ✅ 통과")
    except Exception as e:
        print(f"  {name}: ❌ {str(e)[:100]}")

check(ConvNeXtBlockNPU(32), (torch.randn(1,32,32,32),), "ConvNeXtBlockNPU")
check(BiFPNBlock(32), (torch.randn(1,32,32,32), torch.randn(1,32,16,16), torch.randn(1,32,8,8)),
      "BiFPNBlock", multi=True)
```
