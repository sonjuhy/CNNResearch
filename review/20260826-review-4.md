## 1. Int8 PTQ 완결

5차에서 분리한 **원인 2개가 모두 해소**됐습니다.

### 1.1 원인 (a) — `load_state_dict` 추가

`utils/quantize.py:40-46`이 학습된 체크포인트를 로드하고, 없으면 명확한 메시지와 함께 중단합니다.

```python
ckpt = f"checkpoints/best_{scale}.pt"
if not os.path.exists(ckpt):
    raise RuntimeError(
        f"PTQ 는 학습된 가중치가 필요합니다: {ckpt} 없음. "
        "무작위 초기화 모델은 LayerScale(1e-6) 때문에 양자화 스케일이 붕괴합니다."
    )
model_fp32.load_state_dict(torch.load(ckpt, map_location='cpu'))
```

체크포인트의 gamma가 초기값에서 충분히 커진 것을 확인했습니다.

```
gamma 파라미터 12개, |max| 범위: 1.717e-02 ~ 2.844e-02
초기값 1e-6 대비 → ✅ 학습으로 충분히 커짐
```

5차 §2.1의 gamma 스윕에서 확인한 붕괴 임계(1e-4)를 두 자릿수 이상 상회합니다. **단 1 에포크 학습만으로도 이 조건은 충족**되므로, 실무에서 이 문제가 재발할 가능성은 낮습니다.

### 1.2 원인 (b) — 헤드 `DeQuantStub`

`models/head.py:45`에 `self.dequant = DeQuantStub()`이 추가되고, `forward`에서 conv 출력 직후 float 도메인으로 복귀합니다.

```python
cls_out, reg_out, obj_out = head(feat)

cls_out = self.dequant(cls_out)
reg_out = self.dequant(reg_out)
obj_out = self.dequant(obj_out)

# 이후 * scale / .clamp / .exp 는 전부 float 연산
reg = ((reg_out.flatten(2).permute(0, 2, 1) * scale).clamp(max=8.0)).exp() * stride
```

Conv 연산은 양자화 이득을 그대로 누리고, 스케일·지수 연산만 float에서 수행됩니다.

### 1.3 `utils/quantize.py` 실제 실행 결과

실제 이미지(저주파 패턴 8장, COCO 포맷 어노테이션)를 넣고 **스크립트를 그대로** 실행했습니다.

```
🚀 NPU 배포를 위한 Int8 PTQ 파이프라인 시작...
Calibrating batch 1/2...
Calibrating batch 2/2...
✅ Int8 PTQ 양자화 변환 완료! (저장 위치: exports/sota_detector_nano_int8.pt)

exports/sota_detector_nano_int8.pt   7,032,789 bytes
```

3차에서 추가된 **저장 전 추론 검증 게이트를 통과한** 산출물입니다. 이전 라운드들과 달리, 이번 파일은 실제로 실행 가능한 모델입니다.

### 1.4 백엔드 2종 · 용량

| 백엔드 | 결과 | Int8 state_dict |
| :--- | :--- | ---: |
| **qnnpack** (ARM/모바일/NPU) | ✅ `cls=(1, 8400, 80)`, Int8 Conv 80개 | **7.02 MB** |
| **fbgemm** (x86 서버) | ✅ `cls=(1, 8400, 80)`, Int8 Conv 80개 | 7.36 MB |
| *(참고) FP32* | | *22.63 MB* |

```
BatchNorm 47 → 0   (전량 fuse)
22.63 MB → 7.02 MB (69% 절감)
```

### 1.5 ✨ 양자화 충실도 — "돌아간다"를 넘어

동일 입력에 대해 FP32 모델과 Int8 모델의 출력을 직접 비교했습니다.

| 출력 | FP32 평균 \|v\| | 평균 절대오차 | **상대오차** |
| :--- | ---: | ---: | ---: |
| `cls` | 2.287 | 0.0154 | **0.68 %** |
| `obj` | 2.510 | 0.0134 | **0.53 %** |
| `reg` | 129.123 | 2.3013 | **1.78 %** |

```
argmax 클래스 일치율: 99.8 %
```

Int8 PTQ로서 건전한 수준입니다. 로짓 상대오차가 1% 미만이고 클래스 예측이 99.8% 일치하므로, **양자화로 인한 mAP 손실은 미미할 것으로 예상**됩니다 (실제 COCO에서의 확인은 §4 참조).

> 이 측정은 6라운드 만에 처음으로 **"Int8이 동작한다"를 넘어 "Int8이 FP32를 잘 근사한다"** 까지 확인한 것입니다.

## 2. FP32 경로 회귀 없음

`DeQuantStub` 추가와 downsample `bias=False` 전환이 기존 경로에 영향을 주지 않았습니다.

```
N=8400   레벨별={8: 6400, 16: 1600, 32: 400}   x범위 4.0 ~ 636.0
reg 7.34 ~ 33.86
postprocess boxes=(1000, 4) 범위 0.0 ~ 640.0
grad=None 0/203          파라미터 5.61M

오버피팅: step  0  total=261.605  cls=11.597  box=4.687
          step 30  total=111.065  cls= 0.001  box=1.634     ✅ 수렴

ONNX: opset 17 | BatchNormalization 0 | NPU 비친화 0
      points [8400, 2]  strides [8400]  (정적)

train + eval: Epoch 1 평균 Loss 210.05 → map: 0.0001 / map_50: 0.0006 / mar_100: 0.0470
```

> 파라미터 **개수**가 206 → 203으로 줄어든 것은 downsample conv 3개의 `bias=False` 전환 결과입니다.
> 총 파라미터 **수**(5.61M)는 BN 파라미터로 상쇄되어 변동 없습니다.

## 5. PTQ 추적 이력 정리

Int8 PTQ는 6라운드에 걸쳐 에러가 계속 바뀌었습니다. 겉보기에는 제자리걸음이었지만, 실제로는 **양자화 그래프를 입구에서 출구까지 한 겹씩 벗겨낸 과정**이었습니다.

| 라운드 | 에러 | 원인 | 조치 |
| :---: | :--- | :--- | :--- |
| 1차 | `quantized::conv2d.new` 실행 불가 | `QuantStub`/`DeQuantStub` 부재 | 스텁 삽입 |
| 2차 | `aten::silu.out` 미지원 | SiLU에 양자화 커널 없음 | SiLU → Hardswish |
| 3차 | `promoteTypes: Float QUInt8` | BiFPN·residual의 raw `+` | `FloatFunctional.add` |
| 4차 | `Mul operands should have same data type` | `FloatFunctional.mul(x, gamma)` — gamma가 Float 텐서 | `fold_gamma()` |
| 5차 | `QNNPACK Add` 생성 실패 / `QUInt8 Float` | ① 무작위 가중치 + LayerScale 1e-6 → 스케일 붕괴 ② 헤드의 float 연산 | `load_state_dict` + 헤드 `DeQuantStub` |
| **6차** | **없음** | — | **✅ 완결** |

각 라운드의 수정은 모두 정확했고, 하나를 고칠 때마다 그 뒤에 가려져 있던 다음 층이 드러난 형태였습니다. 이제 숨은 층은 없습니다.

**교훈**: 3차에서 도입한 **"저장 전 추론 검증 게이트"** 가 이 과정의 핵심이었습니다. 그 이전에는 `quantize.py`가 깨진 모델을 저장하고도 성공을 출력했기 때문에, 문제가 존재한다는 사실 자체가 드러나지 않았습니다.

## 7. 검증 재현 스크립트

### 7-1. `quantize.py` 실데이터 실행 (§1.3)

실제 COCO가 없을 때, 스크립트의 코드 경로를 그대로 검증하는 방법입니다.

```python
import torch, sys, os, json
sys.path.insert(0, '.')
from PIL import Image
import numpy as np

root, ann = "/tmp/fakecoco/images", "/tmp/fakecoco/ann.json"
os.makedirs(root, exist_ok=True)
imgs, anns, rng = [], [], np.random.default_rng(0)
for i in range(8):
    small = rng.integers(40, 215, (20, 20, 3), dtype=np.uint8)     # 저주파 자연 이미지 근사
    Image.fromarray(np.array(Image.fromarray(small).resize((640, 640), Image.BILINEAR))) \
         .save(f"{root}/{i}.jpg", quality=90)
    imgs.append({'id': i, 'file_name': f'{i}.jpg', 'width': 640, 'height': 640})
```

### 7-3. Int8 vs FP32 충실도 (§1.5)

```python
import torch, warnings
warnings.filterwarnings('ignore')
import torch.ao.quantization as quant
from torch.ao.quantization import fuse_modules
from models.detector import SOTADetector
from models.neck import ConvModule
from models.backbone import ConvNeXtBlockNPU

ck = torch.load("checkpoints/best_nano.pt", map_location='cpu')
fp = SOTADetector(scale='nano'); fp.load_state_dict(ck); fp.eval()

q = SOTADetector(scale='nano', quantizable=True); q.load_state_dict(ck); q.eval()
for mod in q.modules():
    if isinstance(mod, ConvModule):
        fuse_modules(mod, [['conv', 'bn']], inplace=True)
    elif isinstance(mod, ConvNeXtBlockNPU):
        mod.fold_gamma(); fuse_modules(mod, [['dwconv', 'norm']], inplace=True)
fuse_modules(q.backbone.stem, [['0', '1']], inplace=True)
for ds in q.backbone.downsamples:
    fuse_modules(ds, [['0', '1']], inplace=True)
torch.backends.quantized.engine = "qnnpack"
q.qconfig = quant.get_default_qconfig("qnnpack")
p = quant.prepare(q)
torch.manual_seed(1)
with torch.no_grad():
    for _ in range(3): p(torch.rand(2, 3, 640, 640))
qi = quant.convert(p)

torch.manual_seed(99); x = torch.rand(1, 3, 640, 640)
with torch.no_grad():
    a, b = fp(x), qi(x)
for k in ('cls', 'obj', 'reg'):
    d = (a[k] - b[k]).abs().mean()
    print(f"{k}: 상대오차 {d.item() / a[k].abs().mean().item() * 100:.2f}%")
print(f"argmax 일치율: {(a['cls'].argmax(-1) == b['cls'].argmax(-1)).float().mean().item()*100:.1f}%")
```
