## 1. 프로젝트 현황 파악

COCO 기반 anchor-free 1-stage 객체 검출기 `SOTADetector`를 `nano` / `medium` / `xlarge` 3티어로 스케일링하는 연구 저장소입니다.
구성은 **ConvNeXt 스타일 백본 → 덧셈(Additive) 기반 BiFPN Neck → Decoupled Head**이며, CPU/NPU 배포와 Int8 양자화를 목표로 합니다.

### 1.1 실측 모델 규모

| Scale | Total | Backbone | Neck | Head | FP32 크기 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| nano | 5.53M | 4.83M (87%) | **0.10M (1.8%)** | 0.60M | 22.1 MB |
| medium | 30.59M | 27.81M | 0.39M | 2.38M | 122.3 MB |
| xlarge | 359.57M | 348.11M | 1.97M | 9.48M | 1438.3 MB |

### 1.2 forward 출력 형태 (정상)

```
scale 0 (stride  8): cls (1, 80, 80, 80)  reg (1, 4, 80, 80)  obj (1, 1, 80, 80)
scale 1 (stride 16): cls (1, 80, 40, 40)  reg (1, 4, 40, 40)  obj (1, 1, 40, 40)
scale 2 (stride 32): cls (1, 80, 20, 20)  reg (1, 4, 20, 20)  obj (1, 1, 20, 20)
```

멀티스케일 출력 자체는 설계 의도대로 나옵니다. 문제는 **이 출력을 학습/후처리로 연결하는 부분이 전부 비어 있다**는 점입니다.

## 2. P0 — 치명적 결함 (프로젝트가 성립하지 않는 수준)

### 🔴 P0-1. 학습이 물리적으로 일어나지 않음

`utils/loss.py:100-119`의 `DetectionLoss.forward`는 인자로 받은 `predictions`를 **한 번도 사용하지 않고** 상수 텐서 0을 반환합니다.

```python
# utils/loss.py:110-118 (현재)
loss_cls = torch.tensor(0.0, requires_grad=True)
loss_box = torch.tensor(0.0, requires_grad=True)
loss_obj = torch.tensor(0.0, requires_grad=True)
```

**실측 결과**:

```
grad=None 인 파라미터: 163 / 163
optimizer.step() 후 cls_preds.weight 변화량 max: 0.0
loss_total = 0.0, grad_fn = <AddBackward0>
```

`requires_grad=True`인 leaf 텐서라 `backward()`는 예외 없이 통과하지만, 계산 그래프가 모델과 **연결되어 있지 않아** 모든 파라미터의 `.grad`가 `None`입니다. `optimizer.step()`은 아무 일도 하지 않습니다.

`logs/train_20260825_162222.log`에 Loss가 25배치 내내 `0.0000`으로 기록된 것은 **수렴한 것이 아니라 연결이 끊긴 증거**입니다. 지금까지 실행된 "학습"은 사실상 순전파 벤치마크였습니다.

**원인 사슬**:

| 위치 | 상태 |
| :--- | :--- |
| `utils/loss.py:82-84` `TargetAssigner.forward` | `pass` — 미구현 |
| 저장소 전역 grid point 생성 코드 | **존재하지 않음** (`meshgrid` / `arange` 전수 검색 0건) |
| `utils/loss.py:5-30` `FocalLoss` | 구현됨, **호출처 없음** |
| `utils/loss.py:32-70` `BoxGIoULoss` | 구현됨, **호출처 없음** |

anchor-free 검출기의 핵심 좌표계인 grid point가 코드베이스에 아예 없어서, `TargetAssigner`도 `decode_boxes`도 호출될 수 없는 구조입니다.

### 🔴 P0-2. 후처리(postprocess)가 실행 즉시 크래시

`utils/postprocess.py:30-32`의 `flatten(1).permute(1, 0)`은 **배치 축까지 접어버립니다.**

```python
# 현재 (버그)
cls_preds = scale_preds['cls'].flatten(1).permute(1, 0)   # [B,80,80,80] -> [512000, 1]
reg_preds = scale_preds['reg'].flatten(1).permute(1, 0)   # [B, 4,80,80] -> [ 25600, 1]
```

**실측 결과**:

```
head 출력 cls: (1, 80, 80, 80)
코드가 만드는 cls_preds: (512000, 1)   ← 기대: (6400, 80)
코드가 만드는 reg_preds: ( 25600, 1)   ← 기대: (6400, 4)
postprocess 실행 실패:
  RuntimeError: The size of tensor a (512000) must match the size of tensor b (6400)
                at non-singleton dimension 0
```

추가로 `utils/postprocess.py:52`에서 `filtered_boxes = filtered_reg`로 **raw 회귀값을 디코딩 없이 NMS에 투입**합니다. 형태 버그를 고쳐도 결과는 무의미합니다. 정의만 되어 있는 `decode_boxes`는 어디에서도 호출되지 않습니다.

### 🔴 P0-3. Int8 PTQ 산출물이 추론 불가

`CODE_REVIEW.md`는 PTQ를 *"옵저버 기반 Int8 스케일링을 정확하게 구현… 완벽한 청사진"* 이라 평가했습니다. 실제로 파이프라인을 끝까지 돌리면:

```
Conv2d 총 58개 중 Int8(quantized.Conv2d)로 변환된 것: 58개
FP32 state_dict: 22.21 MB  →  PTQ 후 state_dict: 5.74 MB   (74% 절감 ✓)
Int8 모델 추론 실패:
  NotImplementedError: Could not run 'quantized::conv2d.new' with arguments
                       from the 'CPU' backend
```

용량은 줄지만 **모델이 돌아가지 않습니다.** `utils/quantize.py`에 `QuantStub` / `DeQuantStub`이 없어 float 입력이 그대로 quantized conv로 들어가기 때문입니다. eager-mode PTQ의 필수 요소이며, 기존 리뷰가 "개선 제안"으로 미뤄둔 `fuse_modules`보다 **우선순위가 높은 결함**입니다.

저장되는 것은 "메모리 75% 절약된 배포 모델"이 아니라 **실행 불가능한 state_dict**입니다.

## 3. P1 — 아키텍처 설계 문제

### 🟠 P1-1. BiFPN이 "Depthwise separable"이 아님 — 채널 간 융합이 사실상 부재

`models/neck.py:18-31`의 docstring은 *"Depthwise separable convolutions are used for efficiency"* 라고 명시하지만, 실제로는 `groups=dim` depthwise conv만 있고 **뒤따르는 1×1 pointwise conv가 없습니다.**

> Depthwise Separable = Depthwise (공간 방향) + Pointwise 1×1 (채널 방향)
> 현재 코드는 **후자가 통째로 빠져 있습니다.**

결과가 파라미터 분포에 그대로 드러납니다 — nano의 BiFPN 2블록이 **0.10M (전체의 1.8%)**. 동급 BiFPN 구현이면 통상 0.5~1.0M 규모입니다.

채널 축 mixing이 lateral 1×1 conv 한 번뿐이라, 문서가 강조하는 "멀티스케일 특징 융합"의 표현력이 구조적으로 제약됩니다. **성능이 안 나오는 원인 중 가장 찾기 어려운 지점**이므로 loss 연결 직후에 반드시 손봐야 합니다.

---

### 🟠 P1-2. 헤드를 3개 스케일이 공유하는데 스케일 보정이 없음

`models/head.py:52-57`은 `DecoupledHead` 인스턴스 하나를 stride 8 / 16 / 32에 공유합니다. 파라미터 절약 의도는 타당하지만, 필수 보정이 빠졌습니다.

| 문제 | 설명 |
| :--- | :--- |
| **회귀 스케일 미보정** | stride 32의 박스 크기는 stride 8의 4배인데, 동일 가중치가 동일 출력 범위로 예측합니다. FCOS / YOLOX는 스케일별 learnable `scale` 또는 stride 정규화를 **반드시** 둡니다. |
| **BatchNorm 공유** | `ConvModule` 내부 BN이 3개 스케일의 서로 다른 활성값 분포를 하나의 running stat으로 뒤섞습니다. conv 가중치는 공유하더라도 **BN은 스케일별로 분리**해야 합니다. |
| **양수 제약 없음** | `reg_preds`가 순수 Conv 출력이라 l, t, r, b가 음수로 나올 수 있습니다. `exp` 또는 `ReLU`/`softplus` 제약이 필요합니다. |

---

### 🟠 P1-3. "NPU 최적화" 주장과 실제 연산자의 정면 모순 ⚠️ 가장 큰 문서-코드 괴리

`MODEL_ARCHITECTURE.md`는 *"기존 BiFPN은 복잡한 분모 연산(Division)을 사용하지만, 본 아키텍처는 이를 단순 덧셈으로 대체했습니다. Int8 양자화 시 정확도 붕괴를 막아줍니다"* 라고 강조합니다.

**실제로 내보낸 ONNX(`exports/sota_detector_nano_640.onnx`)의 연산자 분포**:

```
Conv 72, Add 66, Mul 63, ReduceMean 32, Div 28, Sigmoid 23,
Sub 16, Pow 16, Sqrt 16, Erf 12, BatchNormalization 12, Resize 4, MaxPool 4
```

| 발견 | 의미 |
| :--- | :--- |
| `Div` **28개**, `Sqrt` 16, `Pow` 16, `ReduceMean` 32 | 전부 `models/backbone.py:13-18`의 channel-first `LayerNorm`이 분해된 것. **Neck에서 나눗셈 4개를 아끼고 백본에서 28개를 쓰고 있습니다.** |
| `LayerNorm` 주석 *"Hardware & Quantization friendly"* | **사실과 반대.** 대부분의 NPU에서 channel-first LN은 fp fallback이며, LN은 Int8 PTQ에서 가장 정확도가 깨지기 쉬운 연산 중 하나입니다. |
| `Erf` 12개 | exact GELU. NPU 친화 근사(tanh approx) 또는 SiLU/HardSwish 대체가 적용되지 않았습니다. |
| RepVGG 재매개변수화 | ROADMAP Phase 2 명시 항목이나 **전혀 적용되지 않음.** |

즉 **덧셈 융합으로 아낀 이득보다 백본이 유발하는 NPU 비친화 연산이 훨씬 큽니다.** 현재 구조 그대로는 Int8 NPU 매핑이 어렵습니다.

---

### 🟠 P1-4. ONNX export가 요청한 opset을 지키지 못함

`export.py:41`은 `opset_version=14`를 지정하지만, 실제 산출물의 opset은 **18**입니다 (torch 2.13의 dynamo exporter가 승격).

```
opset_import: [('', 18)]
outputs: conv2d_55, conv2d_56, conv2d_57, conv2d_62, ... (자동 생성 이름 9개)
```

- NPU 컴파일러가 opset 14를 요구하면 **이 파일은 사용할 수 없습니다.**
- `output_names`를 지정하지 않아 출력이 `conv2d_55` 같은 자동 이름 9개로 나옵니다. 배포단에서 **어느 텐서가 stride 8의 cls인지 식별 불가능**합니다.
- `dynamic_axes`가 입력에만 지정되어 출력 배치 축 표기는 우연히 따라온 결과입니다.

---

### 🟠 P1-5. 벤치마크 비교가 성립하지 않음

`utils/benchmark.py`는 640×640 텐서를 baseline에 넣지만:

| 모델 | 내부 실제 추론 해상도 |
| :--- | :--- |
| `ssdlite320_mobilenet_v3_large` | **320×320** (내부 transform이 축소) |
| `fcos_resnet50_fpn` | **800** (min_size 기준 확대) |
| `fasterrcnn_resnet50_fpn_v2` | **800** |
| `SOTADetector` | 640×640 (전달값 그대로) |

**서로 다른 해상도끼리 latency를 비교하는 표가 출력됩니다.** 실측:

```
Ours nano       247.5 ms    4.04 FPS   params=5.53M   (640×640)
SSDLite-MBv3    125.0 ms    8.00 FPS   params=5.20M   (내부 320×320)
```

또한 `AGENTS.md`가 요구한 **파라미터 수 / FLOPs / MACs를 전혀 출력하지 않습니다.**

참고로 6스레드 CPU · 640px에서 **4 FPS**는 nano 티어가 표방한 "라즈베리파이·스마트폰 NPU 실시간 추론"과 거리가 있습니다.

### STEP 1 🔴 grid point → TargetAssigner → DetectionLoss 연결 (유일한 블로커)

#### 1-1. Head가 stride 정보와 함께 flatten된 예측을 내도록 변경

후처리·손실 양쪽이 동일한 좌표계를 쓰도록, grid point 생성을 **한 곳에서만** 담당하게 만듭니다.

```python
# models/head.py — SOTAHead에 추가

def __init__(self, num_classes=80, in_channels=128, strides=(8, 16, 32)):
    super().__init__()
    self.num_classes = num_classes
    self.strides = strides
    self.head = DecoupledHead(num_classes, in_channels, hidden_channels=in_channels)
    # P1-2 대응: 스케일별 learnable 회귀 스케일
    self.scales = nn.ParameterList([nn.Parameter(torch.ones(1)) for _ in strides])


@staticmethod
def make_grid_points(h: int, w: int, stride: int, device, dtype):
    """
    피처맵 각 셀의 중심 좌표를 원본 이미지 픽셀 단위로 생성합니다.
    anchor-free 검출기의 기준 좌표계이며, TargetAssigner와 decode_boxes가
    반드시 동일한 함수를 사용해야 학습/추론 좌표가 어긋나지 않습니다.
    Returns: [H*W, 2] (cx, cy)
    """
    ys, xs = torch.meshgrid(
        torch.arange(h, device=device, dtype=dtype),
        torch.arange(w, device=device, dtype=dtype),
        indexing='ij',
    )
    # +0.5: 셀의 좌상단이 아니라 '중심'을 기준점으로 삼습니다.
    points = torch.stack([(xs + 0.5) * stride, (ys + 0.5) * stride], dim=-1)
    return points.reshape(-1, 2)
```

`forward`는 `[B, H*W, C]` 형태로 펼쳐서 반환하도록 바꿉니다. (기존 `[B,C,H,W]` dict 반환은 후처리 버그의 근원이었습니다.)

```python
def forward(self, features):
    cls_list, reg_list, obj_list, point_list, stride_list = [], [], [], [], []

    for feat, stride, scale in zip(features, self.strides, self.scales):
        cls_out, reg_out, obj_out = self.head(feat)
        B, _, H, W = cls_out.shape

        # [B, C, H, W] -> [B, H*W, C]  (배치 축 보존이 핵심)
        cls_list.append(cls_out.flatten(2).permute(0, 2, 1))
        obj_list.append(obj_out.flatten(2).permute(0, 2, 1))

        # 회귀는 stride 단위로 정규화된 l,t,r,b. exp로 양수 보장 후 stride 환산.
        reg = (reg_out.flatten(2).permute(0, 2, 1) * scale).exp() * stride
        reg_list.append(reg)

        pts = self.make_grid_points(H, W, stride, cls_out.device, cls_out.dtype)
        point_list.append(pts)
        stride_list.append(torch.full((H * W,), stride, device=cls_out.device, dtype=cls_out.dtype))

    return {
        'cls':     torch.cat(cls_list, dim=1),    # [B, N, 80]
        'reg':     torch.cat(reg_list, dim=1),    # [B, N,  4]  (l, t, r, b, 픽셀 단위)
        'obj':     torch.cat(obj_list, dim=1),    # [B, N,  1]
        'points':  torch.cat(point_list, dim=0),  # [N, 2]
        'strides': torch.cat(stride_list, dim=0), # [N]
    }
```

> **설계 근거(Rationale)**: `exp()`로 감싼 이유는 l,t,r,b가 반드시 양수여야 하기 때문이고,
> `* stride`를 곱하는 이유는 스케일별 타겟 크기 차이를 정규화해 **공유 헤드가 학습 가능**해지기 때문입니다 (P1-2 해결).

#### 1-2. `TargetAssigner` 구현 — SimOTA 이전에 center-prior 방식부터

`CODE_REVIEW.md`가 권한 SimOTA는 좋은 목표지만, **먼저 단순 assigner로 학습이 도는 것을 확인한 뒤** 교체하십시오. 한 번에 둘 다 넣으면 어느 쪽이 원인인지 분리할 수 없습니다.

```python
# utils/loss.py — TargetAssigner.forward 구현

@torch.no_grad()
def forward(self, points, strides, gt_bboxes, gt_labels):
    """
    Args:
        points:    [N, 2]  grid 중심 좌표 (픽셀)
        strides:   [N]     각 point의 stride
        gt_bboxes: [M, 4]  (x1, y1, x2, y2)
        gt_labels: [M]
    Returns:
        fg_mask:       [N]     bool, positive 샘플 여부
        matched_gt:    [N]     각 point가 매칭된 GT 인덱스 (배경은 무시)
    """
    N = points.shape[0]
    device = points.device
    if gt_bboxes.numel() == 0:
        return (torch.zeros(N, dtype=torch.bool, device=device),
                torch.zeros(N, dtype=torch.long, device=device))

    cx, cy = points[:, 0:1], points[:, 1:2]                      # [N,1]

    # 조건 1: point가 GT 박스 내부에 있는가
    l = cx - gt_bboxes[:, 0].unsqueeze(0)
    t = cy - gt_bboxes[:, 1].unsqueeze(0)
    r = gt_bboxes[:, 2].unsqueeze(0) - cx
    b = gt_bboxes[:, 3].unsqueeze(0) - cy
    in_box = torch.stack([l, t, r, b], dim=-1).min(dim=-1).values > 0   # [N,M]

    # 조건 2: GT 중심 반경(center_radius * stride) 안에 있는가
    #         -> 박스 가장자리 저품질 샘플을 배제해 학습을 안정시킵니다.
    gt_cx = (gt_bboxes[:, 0] + gt_bboxes[:, 2]) * 0.5
    gt_cy = (gt_bboxes[:, 1] + gt_bboxes[:, 3]) * 0.5
    radius = (self.center_radius * strides).unsqueeze(1)               # [N,1]
    in_center = ((cx - gt_cx.unsqueeze(0)).abs() < radius) & \
                ((cy - gt_cy.unsqueeze(0)).abs() < radius)

    candidate = in_box & in_center                                     # [N,M]

    # 한 point가 여러 GT에 걸리면 '면적이 가장 작은' GT에 할당 (FCOS 관행)
    areas = ((gt_bboxes[:, 2] - gt_bboxes[:, 0]) *
             (gt_bboxes[:, 3] - gt_bboxes[:, 1])).unsqueeze(0).expand(N, -1).clone()
    areas[~candidate] = float('inf')
    min_area, matched_gt = areas.min(dim=1)
    fg_mask = min_area < float('inf')
    return fg_mask, matched_gt
```

#### 1-3. `DetectionLoss.forward` 실제 연결

```python
def forward(self, predictions, targets):
    cls_pred  = predictions['cls']      # [B, N, 80]
    reg_pred  = predictions['reg']      # [B, N, 4]
    obj_pred  = predictions['obj']      # [B, N, 1]
    points    = predictions['points']   # [N, 2]
    strides   = predictions['strides']  # [N]

    B, N, _ = cls_pred.shape
    device = cls_pred.device
    total_cls = cls_pred.new_zeros(())
    total_box = cls_pred.new_zeros(())
    total_obj = cls_pred.new_zeros(())
    num_pos_total = 0

    for b in range(B):
        gt_boxes  = targets[b]['boxes'].to(device)
        gt_labels = targets[b]['labels'].to(device)

        fg_mask, matched_gt = self.assigner(points, strides, gt_boxes, gt_labels)
        num_pos = int(fg_mask.sum())
        num_pos_total += num_pos

        # --- Objectness: 전체 point 대상 ---
        obj_target = fg_mask.to(cls_pred.dtype).unsqueeze(-1)
        total_obj = total_obj + self.obj_loss(obj_pred[b], obj_target)

        if num_pos == 0:
            continue

        # --- Classification: positive만, one-hot 타겟 ---
        cls_target = torch.zeros(num_pos, self.num_classes, device=device, dtype=cls_pred.dtype)
        cls_target[torch.arange(num_pos, device=device), gt_labels[matched_gt[fg_mask]]] = 1.0
        total_cls = total_cls + self.cls_loss(cls_pred[b][fg_mask], cls_target)

        # --- Box: l,t,r,b -> (x1,y1,x2,y2) 디코딩 후 GIoU ---
        pred_boxes = decode_boxes(points[fg_mask], reg_pred[b][fg_mask])
        total_box  = total_box + self.box_loss(pred_boxes, gt_boxes[matched_gt[fg_mask]])

    # positive 개수로 정규화 (배치/이미지별 GT 수 편차 흡수)
    norm = max(num_pos_total, 1)
    loss_cls = total_cls / norm
    loss_box = total_box / norm
    loss_obj = total_obj / norm

    return {
        "loss_cls": loss_cls,
        "loss_box": loss_box * 5.0,   # box 가중치는 YOLOX 관행(5.0)에서 시작해 튜닝
        "loss_obj": loss_obj,
        "loss_total": loss_cls + loss_box * 5.0 + loss_obj,
    }
```

### STEP 2 🔴 postprocess 수정

Head가 STEP 1-1처럼 dict를 반환하게 바뀌었다면, 후처리는 다음과 같이 단순해집니다.

```python
def postprocess(predictions, conf_threshold=0.05, iou_threshold=0.5, batch_idx=0):
    cls_pred = predictions['cls'][batch_idx]     # [N, 80]
    reg_pred = predictions['reg'][batch_idx]     # [N, 4]
    obj_pred = predictions['obj'][batch_idx]     # [N, 1]
    points   = predictions['points']             # [N, 2]

    scores = torch.sigmoid(cls_pred) * torch.sigmoid(obj_pred)   # 브로드캐스트 정상
    max_scores, labels = scores.max(dim=1)

    keep = max_scores > conf_threshold
    if not keep.any():
        return torch.zeros((0, 4)), torch.zeros((0,)), torch.zeros((0,), dtype=torch.long)

    # ✅ raw 회귀값이 아니라 반드시 디코딩된 절대좌표를 NMS에 투입
    boxes = decode_boxes(points[keep], reg_pred[keep])

    idx = torchvision.ops.batched_nms(boxes, max_scores[keep], labels[keep], iou_threshold)
    return boxes[idx], max_scores[keep][idx], labels[keep][idx]
```

핵심 변경 2가지:
1. `flatten(1).permute(1,0)` → **배치 축을 보존**하는 형태로 (P0-2 해결)
2. `filtered_boxes = filtered_reg` → **`decode_boxes()` 실제 호출** (P0-2 해결)

### STEP 4 🟠 BiFPN에 pointwise conv 추가 (P1-1)

```python
# models/neck.py
class DWSepConv(nn.Module):
    """
    Depthwise Separable Conv = Depthwise(공간) + Pointwise 1x1(채널).
    기존 코드에 pointwise가 빠져 있어 채널 간 정보 융합이 lateral conv 한 번뿐이었습니다.
    """
    def __init__(self, dim):
        super().__init__()
        self.dw = ConvModule(dim, dim, kernel_size=3, groups=dim)
        self.pw = ConvModule(dim, dim, kernel_size=1, padding=0)

    def forward(self, x):
        return self.pw(self.dw(x))
```

`BiFPNBlock`의 `td_conv_p4` / `td_conv_p3` / `bu_conv_p4` / `bu_conv_p5`를 전부 `DWSepConv(dim)`으로 교체합니다.
예상 효과: nano Neck 파라미터 **0.10M → 약 0.4M**, 채널 축 표현력 확보.

> 여유가 있다면 `F.interpolate(mode='nearest')`는 유지하십시오. bilinear는 NPU 지원이 들쭉날쭉합니다. 반면 bottom-up의 `max_pool2d` 다운샘플은 stride-2 depthwise conv로 바꾸면 정보 손실이 줄어듭니다(연산량과 트레이드오프).

### STEP 5 🟠 헤드 BatchNorm 스케일별 분리 (P1-2)

conv 가중치는 공유하되 BN 통계만 분리하는 것이 가장 저렴한 해법입니다.

```python
# models/head.py — 스케일 수만큼 head를 만들되 conv weight를 공유
self.heads = nn.ModuleList([
    DecoupledHead(num_classes, in_channels, in_channels) for _ in strides
])
# conv 파라미터만 공유하고 BN은 각자 유지
for h in self.heads[1:]:
    for (n0, m0), (n1, m1) in zip(self.heads[0].named_modules(), h.named_modules()):
        if isinstance(m0, nn.Conv2d):
            m1.weight = m0.weight
            if m0.bias is not None:
                m1.bias = m0.bias
```

> 더 간단한 대안: `ConvModule`의 `BatchNorm2d`를 `GroupNorm`으로 교체. 배치 통계 의존이 사라져 스케일 공유가 자연스러워지고 소배치 학습도 안정됩니다. **단, Int8 양자화 관점에서는 BN(fold 가능)이 유리**하므로 NPU 목표를 우선한다면 위의 BN 분리 방식을 택하십시오.

### STEP 6 🟠 NPU 친화 연산자 치환 (P1-3) — 목표가 진심이라면 필수

현재 백본은 NPU 배포 목표와 정면으로 충돌합니다. **실험 브랜치를 나눠** A/B로 비교하십시오.

| 현재 | 치환 후보 | 근거 |
| :--- | :--- | :--- |
| channel-first `LayerNorm` (`Div`/`Sqrt`/`ReduceMean`) | `BatchNorm2d` | Conv에 fold 가능 → Int8에서 연산 자체가 사라짐. NPU 지원 보편적. |
| `nn.GELU()` (`Erf`) | `nn.SiLU()` 또는 `nn.Hardswish()` | Erf는 대부분 NPU 미지원. Hardswish는 정수 연산으로 근사 가능. |
| dwconv `kernel_size=7` | `kernel_size=5` 또는 3 | 7×7 depthwise는 다수 NPU에서 tiling 비효율. |
| (없음) | RepVGG 스타일 재파라미터화 | ROADMAP Phase 2 명시 항목. 학습 시 multi-branch → 추론 시 single 3×3로 융합. |

```python
# models/backbone.py — ConvNeXtBlock의 NPU 친화 변형 예시
class ConvNeXtBlockNPU(nn.Module):
    """
    LayerNorm -> BatchNorm, GELU -> SiLU 치환 버전.
    BN은 추론 시 Conv에 fold되므로 Int8 그래프에서 정규화 연산이 완전히 사라집니다.
    LayerScale(gamma)을 추가해 깊은 스택(xlarge, depth 27)의 학습 안정성을 확보합니다.
    """
    def __init__(self, dim, layer_scale_init=1e-6, drop_path=0.0):
        super().__init__()
        self.dwconv  = nn.Conv2d(dim, dim, kernel_size=5, padding=2, groups=dim, bias=False)
        self.norm    = nn.BatchNorm2d(dim)
        self.pwconv1 = nn.Conv2d(dim, 4 * dim, kernel_size=1)
        self.act     = nn.SiLU()
        self.pwconv2 = nn.Conv2d(4 * dim, dim, kernel_size=1)
        self.gamma   = nn.Parameter(layer_scale_init * torch.ones(dim, 1, 1))
        self.drop_path = DropPath(drop_path) if drop_path > 0 else nn.Identity()

    def forward(self, x):
        residual = x
        x = self.pwconv2(self.act(self.pwconv1(self.norm(self.dwconv(x)))))
        return residual + self.drop_path(self.gamma * x)
```

> **추가 지적**: 현재 `ConvNeXtBlock`에는 원본 ConvNeXt의 **LayerScale과 Stochastic Depth(DropPath)가 둘 다 없습니다.**
> depth 27인 xlarge에서 학습 발산 위험이 큽니다. 위 예시처럼 함께 넣으십시오.

### STEP 7 🟠 Int8 PTQ 실행 가능하게 수정 (P0-3)

```python
# models/detector.py — QuantStub / DeQuantStub 삽입
from torch.ao.quantization import QuantStub, DeQuantStub

class SOTADetector(nn.Module):
    def __init__(self, num_classes=80, scale='nano', quantizable=False):
        ...
        self.quantizable = quantizable
        self.quant   = QuantStub()   if quantizable else nn.Identity()
        self.dequant = DeQuantStub() if quantizable else nn.Identity()

    def forward(self, x):
        x = self.quant(x)                       # float -> quantized tensor 경계
        features = self.neck(self.backbone(x))
        out = self.head(features)
        # 출력 텐서 전부를 float 도메인으로 되돌립니다.
        out = {k: (self.dequant(v) if torch.is_tensor(v) else v) for k, v in out.items()}
        return out
```

### STEP 9 🟠 벤치마크 공정성 확보 + 필수 지표 출력 (P1-5)

```python
def profile_model(model, name, device, img_size=640, num_runs=50, warmup=10):
    model.eval()
    x = torch.randn(1, 3, img_size, img_size, device=device)

    # ✅ baseline의 내부 리사이즈를 무력화해 동일 해상도로 비교
    if hasattr(model, 'transform'):
        model.transform.min_size = (img_size,)
        model.transform.max_size = img_size
    inp = [x[0]] if hasattr(model, 'transform') else x

    with torch.no_grad():
        for _ in range(warmup): model(inp)
        torch.cuda.synchronize() if device.type == 'cuda' else None
        t0 = time.perf_counter()
        for _ in range(num_runs): model(inp)
        torch.cuda.synchronize() if device.type == 'cuda' else None
        latency = (time.perf_counter() - t0) / num_runs * 1000

    params = sum(p.numel() for p in model.parameters())
    # AGENTS.md 요구사항: FLOPs/MACs 출력
    try:
        from torch.utils.flop_counter import FlopCounterMode
        with FlopCounterMode(display=False) as fc, torch.no_grad():
            model(inp)
        flops = fc.get_total_flops()
    except Exception:
        flops = float('nan')

    return latency, 1000 / latency, params, flops
```

출력 표에 **Params(M) / GFLOPs / Latency(ms) / FPS**를 모두 포함시키고, 헤더에 **비교 해상도를 명시**하십시오.
